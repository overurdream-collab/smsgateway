## العيوب المثبتة من الكود والتعديل

1. كان سحب المهمة يسبق فحص جاهزية SIM، فتُحجز المهمة ثم يُبلّغ الخادم بفشلها مع slot=0 إذا لم توجد شريحة. أصبح فحص التصريح وSEND_SMS وREAD_PHONE_STATE وجاهزية SIM قبل polling؛ لا تُستهلك مهمة عندما تكون المتطلبات ناقصة.
2. كانت نتيجة Boolean تجمع غياب الإذن والطابور الفارغ، وتعرض «تمت معالجة مهمة» حتى بعد انتظار callback دون نتيجة. أصبحت النتائج منفصلة: إذن ناقص، شريحة غير جاهزة، طابور فارغ، إرسال أكدته Android، فشل مؤكد، نتيجة غير مؤكدة، وإقرار تعذر تسجيله.
3. يُعاد فحص المتطلبات بعد عودة polling؛ تغير التصريح أو الشريحة يمنع الإرسال. تظل المهمة المحجوزة للمراجعة ولا يُخترع لها فشل أو إعادة إرسال.
4. timeout أو استثناء إرسال أو انقطاع أثناء callback لا يُسجل كفشل مؤكد. فقد ACK لا يؤدي لإرسال SMS مجدداً. يُغلق التصريح المحلي في الحالات التي تحتاج تسوية، وتظل رسالتها ظاهرة ما دام العامل نفسه يعمل.
5. حالة العامل في الواجهة تُقرأ من الخدمة داخل العملية، لا من آخر ضغط زر. توضح رسالة منح إذن Android ضرورة تفعيل التصريح المحلي، وتوضح رسالة التفعيل أنه فُعّل محلياً فعلاً.

فُصل قرار دورة الإرسال عن Android لاختباره بمدخلات اصطناعية. لا يُسجل أو يُحفظ نص الرسالة أو المستلم في هذه الطبقة. لم تتغير الهوية أو Keystore أو عنوان الخادم أو TLS أو المخططات المالية.

## ما أثبتته قراءة الخادم

- `OTP_ENABLED` يتحكم بطلب رمز جديد، و`FIN25_SMS_DISPATCH_ENABLED` يتحكم بسحب المهمة، وهما شرطان منفصلان عن تصريح الهاتف.
- heartbeat الناجح لا يثبت تفعيل dispatch. endpoint السحب يعيد HTTP 503 عندما يكون dispatch معطلاً.
- السحب يعيد المهام pending غير المنتهية، ويحولها إلى leased. الكود المقروء لا يعيد leased المنتهية تلقائياً؛ هذا يمنع إعادة الإرسال الغامض لكنه يحتاج إجراء تسوية مستقل.
- لا يوجد وضع يضمن رسالة واحدة أو allowlist في الخدمة المقروءة. التفعيل المحلي قد يسحب أي مهمة مؤهلة؛ لذلك فحص الطابور لازم قبل التجربة.
- تحقق OTP يشترط حالة sent أو delivered. proofToken الناتج ليس جلسة مالية؛ ربطه بمُصدر هوية موثوق عمل مستقل لم يكتمل إثباته.
- الخادم يخزن `encrypted_body` في قاعدة البيانات، بجانب هاش OTP؛ لا يحقق شرط عدم حفظ محتوى الرمز إطلاقاً. يلزم حسم سياسة الاحتفاظ والمسح، ولا يصح إعلان zero-retention من الكود الحالي.

## فحص Windows مرة واحدة دون تغيير التشغيل

شغّل `scripts/fin25-preflight.ps1` في PowerShell حيث يعمل Docker. يختار خدمة Compose باسم otp فقط إذا كانت واحدة؛ إذا تعددت يطلب ContainerId صريحاً. لا يطلب عنوان النفق ولا يبدله، ولا يشغل أو يوقف الحاويات.

```powershell
powershell -NoProfile -File .\fin25-preflight.ps1
```

يفحص القيم المحملة في الحاوية نفسها، ثم يجري SELECT داخل `BEGIN READ ONLY` لإظهار أعداد الطابور وحالات الأجهزة وآخر heartbeat. لا يطبع DATABASE_URL أو المفاتيح أو الهواتف أو نص OTP. لا يرسل طلب رمز أو رسالة. النتائج لقطة وقتية، وليست ضماناً لعدم وصول مهام جديدة بعد الفحص. إذا تعذر الوصول لقاعدة البيانات يعرض رمز خطأ مقيداً فقط.

قبل تجربة حقيقية: طابق الجهاز والتوقيع، راجع pending_sendable وleased_needing_review، وحدد رقم اختبار مأذون عبر مسار الطلب الأصلي. لا يمكن اعتبار مجرد pending_sendable=1 ضماناً لعزل المستلم. لم يطلب أو يرسل هذا العمل أي SMS.
